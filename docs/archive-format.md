# Archive (export/import) format

> Spec for Phase 10 (`docs/PLAN.md` §12 and §14). Implemented by `domain/archive.py` (records and
> rules), `services/archive_export.py` (writer), `services/archive_import.py` (reader + dry run),
> `services/archive_apply.py` (the transaction), `api/archive.py`, `features/archive/` and the CLI
> (`the_frame_v2 export` / `import`).

Everything here is **boring on purpose**: an archive is a ZIP of JSON, [JSON Lines][jsonl] and the
original image files, with a `sha256sum`-compatible checksum list. No custom container, no custom
encoding, nothing that needs this app to read. `unzip x.tfarchive && sha256sum -c checksums.sha256`
works, `jq` reads every row, and each record shape is published as a JSON Schema in
`docs/schemas/archive/` (draft 2020-12, regenerated by `make gen-api`).

[jsonl]: https://jsonlines.org/

### 12.1 Library archive (`.tfarchive`)

A ZIP file. The extension names what it holds; readers accept the file whatever it is called (the
format is recognized by `manifest.json`, not by the name).

```
manifest.json          { "format": "the_frame_v2.archive", "format_version": 1, "app_version": "…",
                         "created_at": "…", "scope": "full" | "partial", "document_schema": 1,
                         "counts": {…}, "includes_renders": false, "render_key": "1:…" }
data/photos.jsonl  artworks.jsonl  artwork_tags.jsonl  photo_tags.jsonl  tags.jsonl
     tag_categories.jsonl  collections.jsonl  collection_items.jsonl  frame_styles.jsonl
     layouts.jsonl  swatches.jsonl  settings.json
originals/<sha256>.<ext>         stored uncompressed (already-compressed formats)
renders/<artwork_id>.png         optional
checksums.sha256                 every file except itself, `<digest>  <path>`
```

- One JSON object per line, UTF-8, keys sorted; the JSON Schemas in `docs/schemas/archive/` are the
  reference, and unknown fields are ignored on read so a later minor version stays readable.
- **Tag categories** (`tag_categories.jsonl`, and `category_id` on a tag record) were added within
  `format_version` 1 because they are optional both ways: a missing file reads as no categories
  and a missing `category_id` as "Other", so an archive written before them imports unchanged,
  and an older reader ignores both. A full archive carries every category (an empty one is still
  the user's); a partial one carries the categories of the tags it holds.
- **Excluded**: devices, pairing/setup codes, upload sessions, jobs, snapshots, LocalSend senders,
  the FTS index, `artwork_photos` and photo hash aliases (all derived or local), and `cache/`.
  **Built-in** styles and layouts are part of the app — they are seeded on both sides, so exporting
  them would only invent conflicts; an artwork's reference to one survives by id.
- Trashed photos and artworks **do** travel, with their `deleted_at` and `trash_batch_id`: a full
  round-trip restores the library as it was, trash included.
- `render_key` is the renderer version plus the asset-manifest version. The render hash is a
  function of both (`services/render.render_hash`), so an importer reuses a bundled render only
  when they match — otherwise it re-renders, which produces the same pixels anyway.
- A photo whose original file is missing from the library is **left out** of the archive (with a
  warning): an archive must stand on its own, and a damaged library is exactly when a backup
  matters. Artworks that used it still travel; the import leaves those slots as placeholders.
- **Partial export**: selection = collections (optionally with their subtree) and/or artworks →
  those artworks, the photos their documents name, the tags on either, the selected collections
  (a parent left out of the selection makes its child a root on import), and the non-built-in
  templates they were made from. Swatches and settings are library-wide: full scope only.
- Export is a job (`ingest` lane) writing into `exports/<job_id>/`; `GET /exports/{job_id}/download`
  streams it. The CLI writes straight to a path. `exports/` is swept after
  `export_retention_hours`.

### 12.2 Import

1. **Receive** — `POST /imports` then `PATCH /imports/{id}` chunks with `Upload-Offset` (the upload
   protocol, so a dropped connection resumes), into `imports/<id>/archive.tfarchive`. The CLI hard-
   links a local file instead of copying it.
2. **Stage** (a job) — validate before reading anything: member names (no absolute paths, no `..`,
   no backslashes), a bounded expanded size (`max_archive_bytes`), `checksums.sha256` covering
   every member and matching, each `originals/<sha256>` matching its own name, the manifest's
   `format` and `format_version` (a newer one is refused, an older one is migrated), the document
   schema, every record and every artwork document. Then classify and write the report to
   `imports/<id>/report.json`.
3. **Dry-run report** per kind, with exact counts and the interesting items:

   | status | meaning | what apply does |
   |---|---|---|
   | `new` | nothing local claims this row | insert it |
   | `identical` | same id, same content | nothing |
   | `matched` | a local row **is** this row under another id | remap references to it |
   | `conflicting` | same id, different content | the policy decides |

   A row is compared **after translation** — the same artwork in two libraries names the same photo
   under two ids, so the report and the apply pass both compare the record as this library would
   write it, not as it was read.

   Identity is not "same id" alone: a **photo is its bytes** (matched by SHA-256, merged copies
   included — and a local photo that sat in the trash comes back), a **tag is its name**
   (case-insensitive, so tags merge instead of duplicating) — and so is a **tag category**, so the
   seeded People / Events / Themes of two libraries match instead of doubling; a matched tag keeps
   its local category (`matched` writes nothing) — and a **built-in template** is never
   overwritten. `identical` ignores every timestamp, the trash batch and an artwork's
   `document_version`: a no-op save on one side is not a conflict.
4. **Policies** — `POST /imports/{id}/apply` takes a `default`, per-kind overrides and per-item
   overrides keyed `"<kind>:<identity>"`:
   - `keep_mine` (default) — the local row stands; references from the archive point at it.
   - `take_theirs` — the local row is overwritten. An artwork is **snapshotted `pre_import`**
     first, and that snapshot *is* the undo.
   - `keep_both` — insert under a fresh UUID with " (imported)" appended to the name, and remap
     every reference from the archive to the copy.

   A photo is the exception: `take_theirs` on two different images sharing an id cannot mean
   anything (originals are content-addressed), so it behaves as `keep_both`.
5. **Apply** — one transaction, in reference order: tag categories → tags → photos → templates →
   swatches → artworks → collections → collection items → tag links → settings. Photo tag links
   re-index the artworks made of those photos (they carry the photos' tags). Originals are copied to
   `originals/<sha[:2]>/<sha256>.<ext>` first, idempotently by hash (invariant 1). Every id an
   archive carries travels through one set of maps, so an artwork document's `photo_id`s, a
   collection's `parent_id` and `cover_artwork_id`, a **smart collection's filter** (it names tags
   and collections) and `artwork_defaults.style_id` are all rewritten. Documents are stored
   verbatim otherwise — an import is a restore, not a client save, so the composition solver is not
   re-run over it. A photo the archive does not carry leaves the slot as the placeholder a new
   artwork would have (`quality_lock = free`), with a warning.
6. Renders are adopted from the archive when `render_key` matches; everything else written is
   queued for rendering. `imports/` is swept after `import_retention_hours`, and
   `DELETE /imports/{id}` forgets one immediately.

### 12.3 Other exports

- **Rendered images**: a plain ZIP (JPEG at `jpeg_quality`, or PNG) laid out
  `<Collection>/<Sub>/<title or id>.<jpg|png>`; an artwork in several collections is copied into
  each (smart collections included), one in none goes to `Unsorted/`. Anything not yet rendered is
  rendered on the way out. Same selection options as a partial archive.
- **Template files**: `*.tfstyle.json` / `*.tflayout.json` = `{ kind, version, name, document }`
  (`docs/templates.md` §6); references only bundled fonts/textures.
